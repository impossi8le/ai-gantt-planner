# Gantt AI Plan

**AI-native редактор проектного плана: диаграмму Ганта правят на естественном языке, а сроки пересчитывает детерминированное ядро.**

> **Коротко.** Планировать проект в Excel и вручную двигать бары — медленно, а LLM нельзя доверять прямые правки дат. Здесь чат на русском превращает запрос в структурированное намерение, применяет его только через whitelist MCP-инструменты и пересчитывает план в детерминированном scheduler'е. Опасные и массовые операции уходят в подтверждение, а без LLM-ключа работает тот же сценарий на резервном парсере.

**Ссылки:** [дорожная карта](ROADMAP_TO_PRODUCTION.md) · [архитектурный план](docs/ARCHITECTURE_PLAN.md) · [требования](docs/REQUIREMENTS.md) · [пример Excel](samples/example.xlsx) · [демо-анимация](docs/demo.gif)

## Проблема

- Проектный план живёт в Excel: зависимости не пересчитываются, при сдвиге одной задачи остальные даты врут.
- Руководителю проще сказать «перенеси приёмку на неделю» или «передай дизайн Анне», чем искать бар мышью.
- Прямая генерация изменений моделью опасна: LLM не должна удалять задачи или сдвигать весь план без подтверждения.
- Внешний LLM не всегда доступен; демо и тесты должны работать без ключа и без сети.
- Планы приходят в Excel, и загрузка не должна выполнять формулы или макросы из файла.

## Что умеет

- Показывать интерактивную диаграмму Ганта с зависимостями, критическим путём и переключением масштаба: неделя, пять недель, месяц.
- Принимать правки на естественном русском: перенос, удаление, добавление задач, смена зависимостей, исполнителей и полей.
- Показывать изменения мгновенно: SSE-поток отдаёт намерение, обновление плана и текстовое пояснение ассистента.
- Загружать план из `.xlsx`/`.csv` и экспортировать обратно в Excel или CSV.
- Пересчитывать даты после каждой правки: топологическая сортировка, каскадный сдвиг, критический путь.
- Требовать подтверждения для деструктивных и массовых операций; единичные безопасные правки применяются сразу.
- Откатывать изменения через стек снапшотов.
- Работать без `LLM_API_KEY` на детерминированном парсере — для демо, тестов и отладки.

## Как это устроено

Backend — один процесс FastAPI. Внутри него живут доменное ядро, MCP-сервер и LLM-агент. Фронтенд общается с REST API и SSE-потоком; отдельного сервиса-очереди нет.

```text
┌──────────────┐   REST/SSE    ┌──────────────────────────────┐
│   Frontend   │◄────────────►│          Backend (FastAPI)   │
│  React 19    │               │  app/core    — plan,         │
│  Vite + TS   │               │                scheduler,    │
│  Tailwind v4 │               │                versions,     │
└──────────────┘               │                policy,       │
                               │                import/export,│
                               │                sessions      │
                               │  app/mcp     — tools, server │
                               │  app/llm     — router, agent │
                               │  app/api     — REST + SSE    │
                               └──────────────────────────────┘
                     ┌────────────────────────────────────────┐
                     │ LLM-агент = MCP-клиент                 │
                     │   проход 1: intent (structured JSON)   │
                     │   проход 2: русская наррация → SSE     │
                     └────────────────────────────────────────┘
```

**Доменное ядро.** `backend/app/core/scheduler.py` — единственное место, где меняются даты. `_topo` делает сортировку Каном и находит циклы, `forward_pass` считает ранние старты от первого дня проекта, `find_critical_path` — обратный проход и критический путь. Явный сдвиг хранится в `start_override` и удерживается при пересчёте: задача не «прыгает» обратно после следующей правки.

**MCP и политика.** LLM не видит весь план и не вызывает код напрямую. Она обращается к 13 whitelist-инструментам реестра `TOOL_REGISTRY`: чтение схемы и задачи, `compute`, `export`, `shift_tasks`, `set_dependency`, `add_task`, `reassign`, `update_field`, `remove_tasks`, `set_start_day`, `undo`, `help`. Перед выполнением `policy.py` классифицирует действие: `remove_tasks` всегда требует подтверждения, `shift_tasks`, `reassign` и `update_field` — при массовой цели; остальные безопасные действия идут сразу.

**Два прохода LLM.** Первый проход возвращает `Intent{action, targets, params, explanation}` в structured JSON. Второй — стримит русское пояснение по SSE. Если ключа нет, `router.py` разбирает текст детерминированно, включая составные запросы («сделай X и добавь Y») и дедупликацию повторных намерений.

**Сессии и версии.** `SessionStore` держит состояние в памяти: TTL 30 минут, максимум 200 сессий с LRU-вытеснением, отдельный `asyncio.Lock` на сессию. `VersionStack` хранит до 20 снапшотов для undo. Базы данных нет — это осознанный техдолг, зафиксированный в дорожной карте.

**Файлы.** Excel читается через `openpyxl` с `data_only=True` и `read_only=True`: значения без формул и без макросов. Лимиты загрузки — 20 МБ и 100 000 ячеек; CORS ограничен origin'ами фронтенда.

### REST API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/session` | создать сессию с закешированным стартовым планом |
| GET | `/api/session/{id}` | состояние плана |
| POST | `/api/session/{id}/upload` | загрузить свой `.xlsx`/`.csv` |
| GET | `/api/export/{fmt}?session_id=` | экспорт в Excel или CSV |
| POST | `/api/chat/{id}` | чат-запрос без стрима |
| GET | `/api/chat/{id}/stream` | SSE-поток: `intent`, `update`, `delta`, `done`, `pending` |
| POST | `/api/pending/{id}/confirm` и `/cancel` | подтвердить или отменить отложенную операцию |
| POST | `/api/session/{id}/undo` | откатить последнее изменение |

Формат Excel: `задача | описание | исполнитель | длительность | предшественники`.

### Шкала Ганта

Бары позиционируются по дням с фиксированной шириной дня; при длинном плане появляется горизонтальный скролл. Переключатель «Показывать» предлагает три режима:

- **1 неделя** — семь дней детально, с навигацией «‹ ›» и подписью «Неделя N из M · дни X–Y».
- **Недели · 5** — страница из пяти недель (35 дней) с пагинацией.
- **Месяц** — весь план со шкалой по месяцам; задачи длиннее месяца помечаются значком и подсказкой.

## Инженерные находки

1. **LLM не имеет права писать даты.** Модель возвращает только намерение; применение идёт через MCP-инструменты, а все даты пересчитывает scheduler. Поэтому один и тот же текстовый запрос даёт воспроизводимый план, а ошибка модели не может создать противоречивое расписание.

2. **Подтверждение как часть протокола, а не UI-подсказка.** `policy.py` классифицирует действие до выполнения. `remove_tasks` всегда попадает в `pending`, массовые `shift_tasks`/`reassign`/`update_field` — при `targets=all` или более одной задачи. Подтверждение и отмена — отдельные REST-эндпоинты, а не флаг в запросе чата.

3. **Whitelist вместо свободного исполнения.** В реестре ровно 13 инструментов с обязательными и опциональными аргументами; `execute` ищет имя в `TOOL_REGISTRY` и возвращает `unknown_tool` для всего остального. В коде нет `eval`/`exec`; `compute` — фиксированные pandas-агрегации, а не произвольный код от модели.

4. **Детерминированный fallback — не заглушка.** Без LLM-ключа `router.py` разбирает команды по ключевым словам, разрезывает составные запросы по союзам, не трогая кавычки, и дедуплицирует повторные намерения. Весь сценарий «загрузка → чат → экспорт» работает офлайн, поэтому тесты не зависят от внешнего API.

5. **Стрим через `fetch` + `ReadableStream`.** Фронтенд не использует `EventSource`: он читает SSE-поток вручную и разбирает события по мере поступления. Это позволяет отдавать `delta` по мере генерации и не держать отдельное соединение для каждого события.

6. **Экономия состояния с явными границами.** Сессия ограничена TTL и LRU, стек версий — 20 снапшотами, загрузка — 20 МБ и 100 000 ячеек. Ограничения заданы в конфиге и применяются на входе, а не после разбора большого файла.

## Быстрый старт

Требования: Python 3.12+, Node.js 20+.

```bash
git clone https://github.com/impossi8le/ai-gantt-planner.git
cd ai-gantt-planner
```

### Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload    # http://localhost:8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173
```

Vite проксирует `/api` на порт 8000. Откройте `http://localhost:5173`: появится Гант с закешированным стартовым планом. Без `LLM_API_KEY` ассистент работает на детерминированном парсере.

### Docker Compose

```bash
export LLM_API_KEY=...           # опционально
docker compose up --build
# фронт: http://localhost:8080, nginx раздаёт статик и проксирует /api на backend
```

### LLM: ключ или fallback

- **Google AI Studio (по умолчанию)** — достаточно задать `LLM_API_KEY`; модель по умолчанию `gemini/gemini-3.6-flash`, `BASE_URL` не нужен.
- **OpenAI-совместимый роутер** — задайте `LLM_API_KEY`, `LLM_MODEL` и `BASE_URL`; запросы идут через LiteLLM.
- **Без ключа** — работает детерминированный разбор команд; этого достаточно для демо и тестов.

Переменные окружения читаются через `pydantic-settings` из `.env`. Таймаут LLM — 60 секунд, до трёх повторов.

### Проверки

```bash
cd backend
python -m pytest -q
```

В `backend/tests` четыре файла и 40 тестов: API, MCP-инструменты, router и scheduler. Тот же pytest запускается в CI на Python 3.12.

## Статус и ограничения

- **Демо больше не доступно.** Приложение разворачивалось на собственной VM по адресу `http://95.142.46.44:8080`; сейчас этот стенд не работает. Ссылка намеренно убрана, чтобы README не вёл на мёртвый адрес. Посмотреть проект можно локальным запуском или через Docker Compose.
- Проект выполнен как тестовое задание на позицию full-stack разработчика AI-native продукта; это не production-сервис.
- Сессии хранятся **в памяти процесса**: после перезапуска планы и история версий теряются. Базы данных нет — техдолг описан в `ROADMAP_TO_PRODUCTION.md`.
- Аутентификации нет: идентификатор сессии — это и есть доступ к плану. Для публичного развёртывания нужен отдельный слой доступа.
- Backend и MCP работают в одном процессе. Вынос MCP в отдельный процесс не меняет контракт, но в текущем виде не реализован.
- CI/CD в `deploy.yml` запускается на ветке `master`: сначала pytest, затем SSH-деплой на VM. Для деплоя нужны секреты `SSH_KEY`, `SSH_HOST`, `SSH_USER` и `LLM_API_KEY`; без них работает только тестовая job.
- В репозитории остались служебные артефакты Playwright MCP (`.playwright-mcp/`). Они не участвуют в работе приложения.
